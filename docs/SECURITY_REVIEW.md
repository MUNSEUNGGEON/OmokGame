# 보안 검토

## 해결한 항목

### HIGH — 소스 내 자격 증명

- 위치: DB 연결, SMTP 유틸리티 2개, 날씨·주소 API
- 조치: 실제 값을 제거하고 `config.AppConfig`를 통한 환경 변수 주입으로 변경
- 후속 조치: 기존 DB 비밀번호, Gmail 앱 비밀번호, API 키를 반드시 폐기·재발급

### HIGH — SQL 문자열 결합

- 위치: 랭킹 검색, 승패 갱신, 동적 컬럼명
- 조치: 사용자 값은 PreparedStatement로 바인딩하고 동적 컬럼은 허용 목록 적용

### HIGH — 관리자 비밀번호 조회

- 위치: `ui.AdminFrame.performSearch`
- 조치: SELECT 대상에서 password를 제거하고 UI에는 마스킹 문자열만 표시

## 남은 위험

### HIGH — 평문 비밀번호 저장

`Users.password`를 평문으로 저장·비교하고 임시 비밀번호도 그대로 갱신한다. Argon2id 또는 bcrypt 해시를 저장하도록 DB와 로그인 흐름을 함께 마이그레이션해야 한다.

### HIGH — 평문 네트워크 인증

클라이언트와 서버가 암호화되지 않은 TCP에서 구분자 기반 문자열로 비밀번호를 보낸다. TLS 또는 HTTPS 기반 API로 전환하기 전에는 신뢰할 수 없는 네트워크에서 사용하면 안 된다.

### HIGH — 관리자 인증 모델

관리자 자격 증명은 환경 변수로 이동했지만 단일 공유 계정 방식이다. DB 사용자 역할과 감사 로그를 사용하도록 재설계해야 한다.

### MEDIUM — 입력과 프로토콜 검증

메시지 길이, 필드 수, 방 번호, 좌표, 플레이어 권한, 턴 상태를 서버 경계에서 일관되게 검증해야 한다. 잘못된 메시지는 연결 단위 오류로 처리하고 전체 서버 스레드에 영향을 주지 않아야 한다.

### MEDIUM — 개인정보

주소, 전화번호, 생년월일, 프로필 이미지와 채팅을 처리한다. 보존 기간, 삭제 정책, 접근 권한, 로그 마스킹이 필요하다.
